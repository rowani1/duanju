# 跨技能数据交接协议 v1.0

## 协议目的

确保 packaging → title-forging → writing 三个技能之间的数据无缝衔接，消除信息断层。

---

## 一、packaging → title-forging

### 必须传递字段

| 字段名 | 类型 | 必填 | 示例 |
|--------|------|------|------|
| 主类 | 枚举 | ✅ | `总裁` |
| 子类 | 字符串 | ✅ | `追妻火葬场` |
| 一句话选题 | 字符串 | ✅ | `离婚三年后带娃回国，前夫追疯了` |
| 核心卖点 | 字符串 | ✅ | `身份反转+带娃引爆+前夫追妻` |
| 女主身份 | 字符串 | ✅ | `前豪门少奶奶，离婚后独立创业` |
| 男主身份 | 字符串 | ✅ | `顾氏集团总裁，前夫` |
| 核心关系 | 字符串 | ✅ | `前夫妻，因误会离婚` |
| 核心冲突 | 字符串 | ✅ | `孩子身份暴露引发追妻` |
| 最强反转 | 字符串 | ✅ | `女主才是真正的资本方` |

### 可选传递字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 反派角色摘要 | 字符串 | 帮助标题强化对手盘信息 |
| 目标情绪 | 字符串 | 帮助标题选择情绪词方向 |
| 短剧适配判断 | 字符串 | 帮助标题判断用番茄风还是红果风 |

---

## 二、packaging → writing

### 必须传递字段（全六包）

| 包名 | 必需内容 |
|------|---------|
| 题材包 | 主类、子类、一句话选题、核心卖点、目标情绪、风险点 |
| 人设包 | 女主人设卡、男主人设卡、反派角色、关系链、核心冲突 |
| 标题简介包 | 确定书名、一句话卖点、简介、标签 |
| 开篇包 | 开篇场景、第一冲突、第一反转、章末钩子、前3章节奏 |
| 章纲包 | 总纲、分章表（每章核心事件+情绪点+反转点+钩子） |

### 角色状态初始化

writing 收到 packaging 数据后，必须从人设包中提取并锁定：

- 每个角色的初始情绪状态
- 每个角色的初始关系位置
- 每个角色的已知/未知信息边界

---

## 三、title-forging → packaging（回填）

### 回填字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 书名候选（第一梯队） | 列表 | 10 个 |
| 书名候选（第二梯队） | 列表 | 10 个 |
| 推荐书名 | 字符串 | 第一梯队中最强的 1 个 |
| 命名方向 | 字符串 | 主打法 + 次打法 |

回填后，packaging 将推荐书名填入标题简介包的"书名"字段。

---

## 四、数据格式规范

### 人设卡标准格式

```markdown
### [角色名]
- 身份：
- 表面性格：
- 真实驱动：
- 最怕失去什么：
- 最能刺痛对方的话/事：
- 对这段关系的初始态度：
- 当前情绪状态：【初始/续写时必填】
- 当前关系位置：【初始/续写时必填】
```

### 章纲条目标准格式

```markdown
### 第X章
- 核心事件：
- 情绪主轴：
- 反转点：
- 结尾钩子：
- 字数预算：2000-4000字
```

---

## 五、协议执行规则

1. 上游技能输出时，必须按本协议格式组织数据
2. 下游技能接收时，必须检查必填字段是否完整
3. 字段缺失时，下游技能应主动询问用户补充，不要猜测
4. 协议版本号随技能重大升级同步更新
